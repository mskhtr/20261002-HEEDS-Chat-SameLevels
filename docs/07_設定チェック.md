# プログラム設定と HEEDS の突き合わせ（事前チェック）

この文書は、チャットで解析を回す**前に**、プログラム側の設定名と HEEDS プロジェクト内の実名が一致しているかを確認する方法です。

解析は実行しません。名前だけを見ます。

接続の全体手順は [05_HEEDS接続.md](05_HEEDS接続.md)、名前の約束は [06_HEEDSファイルを作るとき.md](06_HEEDSファイルを作るとき.md) です。

## 何を比べるか

プログラムは HEEDS の画面を見ていません。次の **英字の名前** だけで探します。このチェックは、その名前が両方にあるかを突き合わせます。

| 項目 | プログラム側（基準） | HEEDS 側 |
| --- | --- | --- |
| `.heeds` の場所 | `.env` の `HEEDS_PROJECT_PATH` | そのパスのファイル |
| 実行ファイル | `.env` の `HEEDS_EXE` | そのパスの `HEEDSMDO.exe` |
| Study 名 | `catalog.yaml` の `heeds_name`。`.env` の `HEEDS_STUDY_<ID大文字>` があればそちら | プロジェクト内の Study 表示名 |
| 入力変数名 | 引数に渡した CSV の「変数名」列。省略したときは照合しない | 各 Study の AgentVariable 名 |
| 出力名 | 照合しない | 各 Study の Response 名を参考表示する |

入力変数の名前と範囲はカタログにありません。このチェックで変数も見るときは、CSV を引数に渡します。チャットでは、アップロードした CSV で同じ照合をします。出力名はカタログに無く、HEEDS にある Response 名を参考として出します。

プロセス名や解析ファイル名は比べません。

比べる Study は、カタログの `studies` に書いてあるもの全部です。今回のチャットが「衝突安全だけ」でも、チェックは NVH 側の Study も見ます。

## いつ実行するか

- `.env` を書いた直後
- HEEDS で Study 名・変数名・出力名を変えたあと
- `catalog.yaml` の `heeds_name` や `studies` を変えたあと
- チャットで `Study not found` や `Variable not found`、出力が空になるとき

チャット起動の前に一度通すのが安全です。

## 準備

1. [セットアップ.md](セットアップ.md) のとおり **Python 3.12** で `.venv` を作り、ライブラリを入れる
2. `.env.example` をコピーして `.env` を作り、`HEEDS_EXE` と `HEEDS_PROJECT_PATH` を書く
3. Study 名がカタログの `heeds_name` と違う PC では、`HEEDS_STUDY_*` も書く
4. コマンドは **Windows PowerShell** を使う

## 実行方法

プロジェクトフォルダ（`20261002_HEEDS-Chat-SameLevels`）で、次のどちらかです。

```powershell
.\.venv\Scripts\python.exe check_heeds_project.py
```

記入済みの変数 CSV も比べるときは、そのファイルを引数にします。

```powershell
.\.venv\Scripts\python.exe check_heeds_project.py .\sample.csv
```

またはエクスプローラで **`check_heeds.bat` をダブルクリック**します。CSV を渡すときは、PowerShell で上の2つ目を使います。

終わるまで数十秒かかることがあります（HEEDS を開くため）。解析そのものは回りません。待ち時間は 180 秒です。

中では `runs/check_<UTC時刻>/` を作り、`heeds/scripts/check_project_template.py` にパスと Study 名を埋め込んで `HEEDSMDO.exe -b` で開きます。Study の `run` は呼びません。

## 画面の見方

結果は次の順です。

1. **結果** … 合っているか、ずれているか
2. **合っているところ** … パス、開けたプロジェクト、一致した Study 名。CSV を渡したときは一致した変数も
3. **直すこと** … 無い名前、CSV と違う変数。無ければ「ありません」
4. **参考** … 合否に使わないもの。プログラムが使わない Study、HEEDS にある変数、実行後の表見出しになる Response 名

Study 名の行には、名前の出所が付きます。`catalog.yaml` か、`.env の上書き` かです。

CSV を省略したときは、変数の一致は見ません。出力名はプログラム側に無いので、HEEDS にある名前を参考として出します。

詳細は `runs/check_<時刻>/` に残ります。標準出力と標準エラーは `heeds_stdout.txt` と `heeds_stderr.txt` です。

終了コードは、合っていれば 0、ずれていれば 1 です。

## 直す場所

| NG の内容 | 直す場所 |
| --- | --- |
| `HEEDS_EXE` / `HEEDS_PROJECT_PATH` が無い、またはファイルが無い | `.env` のパス |
| Study 名が HEEDS にない | カタログの `heeds_name` を画面の名前に合わせる。この PC だけ違うなら `.env` の `HEEDS_STUDY_*`。または HEEDS 側の名前をカタログに合わせる |
| 入力変数が CSV と違う | CSV の変数名と HEEDS の AgentVariable 名を揃える |
| `heeds_name` が空 | `catalog.yaml` のその試験に `heeds_name` を書く。空だと読み込み時にエラーになる |

カタログを変えたあとは、チャットサーバーを再起動してください。このチェック自体は、実行のたびに YAML を読み直します。

## このチェックで分からないこと

| 分かること | 分からないこと |
| --- | --- |
| パスと Study 名がプログラムと HEEDS で一致している | 解析モデルに変数がタグ付けされているか |
| カタログに書いた Study がプロジェクト内にあるか | 計算結果の正しさ、Response が値を取れているか |
| CSV を渡したときの変数名の過不足 | GUI で手動実行できるか（別途一度回して確認） |
| プログラムが使わない Study の名前 | チャットの言葉が意図どおり要件に結びつくか（それは開始画面と確認文で見る） |

名前が通っても解析が失敗する場合は、HEEDS の GUI で同じスタディを手動実行し、[05_HEEDS接続.md](05_HEEDS接続.md) を見てください。
