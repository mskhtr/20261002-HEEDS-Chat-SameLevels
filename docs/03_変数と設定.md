# 変数と設定（初学者向け）

この文書では、プログラムに渡す「設定値」を3つの層に分けて説明します。

全体像は [01_はじめに.md](01_はじめに.md)、ファイルの役割は [02_ファイルの関連.md](02_ファイルの関連.md) です。

## 3つの層

| 層 | 置き場 | 誰が書くか | 例 |
| --- | --- | --- | --- |
| 環境設定 | `.env`（雛形は `.env.example`） | あなた（必須） | API キー、`HEEDS_EXE` |
| カタログ | `heeds/catalog.yaml` | 言葉と試験を決めるとき | `label: 衝突安全`、`heeds_name: Study_stress` |
| チャット入力 | ブラウザに打つ一文と、添付 CSV | あなた（実行のたびに） | 「衝突安全を確認したい」 |

覚え方:

- **機械の住所・鍵** → `.env`
- **やってよい試験のルールブック** → `catalog.yaml`
- **今回やりたいこと** → チャットと CSV

## 1. 環境設定（`.env`）

### 作り方

```powershell
copy .env.example .env
```

そのあと Visual Studio Code で `.env` を開き、空欄を埋めます。  
**.env は秘密情報なので、GitHub などに上げないでください。**（`.gitignore` で除外済みです）

さらに詳しい HEEDS 側の手順は [05_HEEDS接続.md](05_HEEDS接続.md)、プロジェクト作成時の名前の約束は [06_HEEDSファイルを作るとき.md](06_HEEDSファイルを作るとき.md)、設定名の突き合わせは [07_設定チェック.md](07_設定チェック.md) です。

### LLM（AI）関連

AI は **Azure OpenAI** です。使うのは、HEEDS が終わったあとの短い要約だけです。どの試験を実行するかは、このキーが無くても `catalog.yaml` から決まります。キーが空だと、確認と実行はでき、要約の代わりに「結果は下の表です。」と出ます。

`LLM_PROVIDER=azure` にします。それ以外だと要約は定型文になり、HEEDS 自体は動きます。

| 変数名 | 必須 | 意味 | 書き方例 | どこで使うか |
| --- | --- | --- | --- | --- |
| `LLM_PROVIDER` | 要約に使うなら | 使う AI の種類 | `azure` | `heeds/summary.py` |
| `AZURE_OPENAI_API_KEY` | 要約に使うなら | Azure OpenAI のキー | （Azure ポータル） | `heeds/summary.py` |
| `AZURE_OPENAI_ENDPOINT` | 要約に使うなら | Azure のエンドポイント URL | `https://xxxx.openai.azure.com/` | `heeds/summary.py` |
| `AZURE_OPENAI_DEPLOYMENT` | いいえ | デプロイ名。空なら `gpt-4o` | `gpt-4o` | `heeds/summary.py` |
| `OPENAI_API_VERSION` | いいえ | API の版。空なら `2024-10-21` | `2024-10-21` | `heeds/summary.py` |

### HEEDS 関連

| 変数名 | 必須 | 意味 | 書き方例 | どこで使うか |
| --- | --- | --- | --- | --- |
| `HEEDS_EXE` | はい | `HEEDSMDO.exe` のフルパス | `C:/Program Files/Siemens/HEEDS/2504/HEEDSMDO.exe` | `cli_backend.py` |
| `HEEDS_PROJECT_PATH` | はい | 使う `.heeds` プロジェクトのフルパス | 自分の `.heeds` のフルパス | `cli_backend.py` |
| `HEEDS_TIMEOUT_SEC` | いいえ | HEEDS 実行の待ち時間（秒） | `3600`（既定） | `cli_backend.py` |
| `HEEDS_STUDY_<ID>` | いいえ | その試験 ID の画面名を、カタログの `heeds_name` から上書きする | `HEEDS_STUDY_STRESS=別の名前` | `catalog.py` |

パスの区切りは `/` を推奨します。

### カタログの試験 ID と HEEDS Study 名の対応

同じ「静荷重解析」でも、場所ごとに呼び方が違います。

| 呼び方 | どこに出てくるか | 例 | 誰が決めるか |
| --- | --- | --- | --- |
| 人が話す名前 | チャットに打つ言葉 | 「衝突安全」 | カタログの `label` と `aliases` |
| カタログの試験 ID | `studies` の `id` | `stress` | カタログ |
| 試験の日本語名 | 確認文と開始画面 | 静荷重解析 | カタログの `name_ja` |
| HEEDS の Study 名 | HEEDS の画面 | `Study_stress` | 既定はカタログの `heeds_name`。この PC だけ違うときは `.env` |

プログラムは次の順で画面名を決めます。

```text
環境変数 HEEDS_STUDY_STRESS があればそれを使う
無ければ catalog.yaml の stress の heeds_name を使う
```

環境変数の名前は、試験 ID を大文字にしたものです。`stress` なら `HEEDS_STUDY_STRESS`、`eigenvalue` なら `HEEDS_STUDY_EIGENVALUE`。この対応は Python の辞書には書いてありません。ID から機械的に作ります。

同梱時の初期値は次です。画面名をカタログのとおりに HEEDS で作っていれば、`.env` に Study 名の行は要りません。

| カタログの試験 ID | 日本語 | カタログの `heeds_name` | 上書きする環境変数 |
| --- | --- | --- | --- |
| `stress` | 静荷重解析 | `Study_stress` | `HEEDS_STUDY_STRESS` |
| `crash` | 衝突解析 | `Study_crash` | `HEEDS_STUDY_CRASH` |
| `eigenvalue` | 固有値解析 | `Study_eigen` | `HEEDS_STUDY_EIGENVALUE` |
| `frf` | 周波数応答解析 | `Study_frf` | `HEEDS_STUDY_FRF` |

- HEEDS で Study の表示名を変えたら、**カタログの `heeds_name` か、`.env` の上書きを同じ名前にする**
- カタログの試験 ID（`stress`）を、HEEDS の Study 名だと思わない
- プロジェクトを新規作成するときのチェックリストは [06_HEEDSファイルを作るとき.md](06_HEEDSファイルを作るとき.md) です

## 2. カタログ（`heeds/catalog.yaml`）

カタログは「このチャットが受け付けるもの」のルールブックです。開始画面の表、入力欄の例、確認文、実行する試験 ID、Study 名の既定は、すべてここから作ります。`app.py` に同じ表は書いてありません。

読み込み時に次を検査します。どれかに当てはまると、その処理はエラーになります。

- `studies` または `design_requirements` がリストでない
- 試験の `id` が空、または重複している
- `name_ja` または `heeds_name` が空
- 要件の `label` が空、または `study_ids` が空
- `study_ids` に、`studies` に無い ID がある

### 2.1 `design_requirements`（設計要件）

チャットの言葉を、どの試験セットに対応させるかの定義です。

| フィールド | 意味 | 同梱時の例 |
| --- | --- | --- |
| `id` | 内部用の識別子。チャットには出さない | `crash_safety` |
| `label` | ユーザーが言う主な名前。開始画面の表と、入力欄のボタンになる | `衝突安全` |
| `aliases` | 同じ要件として扱う別名。文にこの文字列が含まれれば、その要件とみなす | `衝突`, `乗員保護` |
| `study_ids` | 実行する試験 ID。上から順に、欠けなく実行する | `stress`, `crash` |
| `summary` | 人向けの短い説明。実行ロジックは `study_ids` を見る | （任意） |

`aliases` は AI へのヒントではありません。`plan.py` が「この文字列が文に含まれるか」で判定します。類義語を増やしたいときは、ここに足してチャットを起動し直します。カタログに無い言い換え（例: 「剛性」）は、要件として扱いません。

短い語は長い語に含まれます。`衝突` を別名にすると、「衝突安全」にも「衝突」が含まれます。意図しない文で要件ありと判定されないように、語を選びます。

同梱時の対応:

| label | aliases | study_ids |
| --- | --- | --- |
| 衝突安全 | 衝突、乗員保護 | `stress`, `crash` |
| NVH | 振動、騒音、共振、周波数 | `eigenvalue`, `frf` |

言葉の追加や、実行する解析の入れ替えは [08_試験の種類を変える.md](08_試験の種類を変える.md) です。Python の追記は要りません。

一文に複数の要件の言葉があると、カタログの並びで両方を採用します。同梱時に「衝突安全と NVH」と書くと、4試験が対象になります。

一度要件が決まると、そのチャットでは次のメッセージに言葉が無くても要件は残ります。「はい」だけの同意が通るのはこのためです。別の要件の言葉を送ると、保存していた要件 ID は、その文に含まれたものへ置き換わります。足し算ではありません。

### 2.2 入力変数はカタログに書きません

探査する変数の名前・下限・初期値・上限・刻みは、ユーザーがアップロードした CSV の行です。結果表の変数列も、CSV に書いた変数名のままです。

CSV の列は `sample.csv` と同じです。

| 列 | 内部の名前 | 意味 |
| --- | --- | --- |
| 変数名 | `name` | HEEDS の AgentVariable 名。英字で始める |
| 下限値 | `lower` | 探査の下限 |
| 初期値 | `baseline` | 開始時の値。下限と上限の間 |
| 上限値 | `upper` | 探査の上限 |
| 刻み | `step` | 水準の間隔。0 より大きい |

1行目は日本語（変数名、下限値、初期値、上限値、刻み）でも、英語（name、lower、baseline、upper、step）でも読めます。文字コードは UTF-8（BOM 付きを含む）または CP932 です。

行を足した名前（`width2` など）は、その綴りの AgentVariable を、実行する Study に作ります。エラーが1行でもある CSV は、一部だけ採用せず、全部読みません。

照合は CSV をアップロードしたときに、カタログに載っている **すべての** Study の AgentVariable と行います。今回の要件が使う Study だけ、ではありません。

### 2.3 `studies`（実行可能な試験）

ホワイトリストです。ここに無い `id` は実行できません。

| フィールド | 意味 | 同梱時の例 |
| --- | --- | --- |
| `id` | カタログ上の試験 ID | `stress` |
| `name_ja` | 確認文と開始画面に出す日本語名 | `静荷重解析` |
| `description` | 人向けの説明。実行ロジックは見ない | （任意） |
| `heeds_name` | HEEDS 画面の Study 名の既定 | `Study_stress` |

結果表の出力列は、実行した Study にある HEEDS の Response です。見出しは通常その Response 名で、カタログには書きません。同じ名前が複数試験にある場合や入力列と同名の場合だけ、値を上書きしないよう `試験ID.Response名` にします。

## 3. チャット入力（あなたが毎回書くもの）

### 設計要件

同梱時は、次のどちらか（または両方）を文章に含めます。

| 書いてよい例 | 実行される試験 |
| --- | --- |
| `衝突安全を確認したい。` | `stress` と `crash` |
| `乗員保護を見たい` | 上と同じ（別名） |
| `NVHを確認したい。` | `eigenvalue` と `frf` |
| `振動を見たい` | 上と同じ（別名） |

試験 ID を英語で書いても、それが `label` か `aliases` に無ければ要件にはなりません。

### 同意

確認文のあとに、次のような短い返事をすると実行します。

`はい`、`実行して`、`お願いします`、`ok`、`yes`、`了解`、`大丈夫`、`進めて`、`合っています` など。

空白と句読点を除いた文が、登録済みの短い返事と完全に一致するときだけ同意にします。
たとえば `はい、お願いします` のように二つの返事をつないだ文や、説明を付けた文は同意にしません。
次の語が含まれるときも同意にしません。

- 変数や範囲の語: `thickness`、`width`、板厚、幅、刻み、下限、上限
- 取りやめの語: 変えて、変更、違う、キャンセル、やめて、中止
- カタログの `label` と `aliases` そのもの（同梱時なら「衝突」「nvh」など）

新しい CSV を同じメッセージに付けたときも、実行せず、確認からやり直します。

### 変数

チャット本文の数値では範囲を変えません。開始時の `sample.csv` をダウンロードして記入し、添付します。CSV は1ファイルだけです。

## よくある勘違い

| 勘違い | 実際 |
| --- | --- |
| カタログの `stress` が HEEDS の Study 名 | 違う。Study 名は `heeds_name`（既定 `Study_stress`）。上書きは `.env` |
| `.env` に `HEEDS_STUDY_*` を4行書かないと動かない | カタログの `heeds_name` と画面名が同じなら、書かなくてよい |
| `.env.example` を編集すれば動く | 動かない。必ず `.env` を作る |
| `chainlit.md` を直せば開始画面が変わる | 次回のチャット開始でカタログから上書きされる |
| ホストの Python で `import HEEDS` できる | できない。`HEEDSMDO.exe -b` の中だけ |
| AI が試験を選んでいる | 選んでいない。含まれる言葉で `plan.py` が ID を決める |
| チャットに試験 ID を英語で書けばよい | 「衝突安全」「NVH」など、カタログの言葉で書く |
